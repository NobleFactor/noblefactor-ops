# Plan: Star Release and Self-Install

<!--
REQUIRED: star must be installable from a release binary.
This enables the quality gate plan - repos need a working star binary

-->

## Summary

Implement an LKG (Last Known Good) release process for `star` with automatic updates via `self upgrade`. This is a prerequisite for the quality gate plan - every repo needs a working `star` binary to generate its `.pre-commit-config.yaml`.

## Goals

1. **LKG releases**: `make release` validates and creates immutable versioned binaries
2. **Validation gate**: Release only succeeds if star passes all behavior tests
3. **Bootstrap install**: `curl | bash` for initial install on machines without star
4. **Self install**: `star self install` generates completions, man pages, config (offline)
5. **Self upgrade**: `star self upgrade` checks for and installs latest LKG (network)

### Gaps

1. **self install requires path argument** - should default to `~/.local`
2. **ops/ scripts are external** - should be embedded in binary via `//go:embed`
3. **No LKG check** - just copies running binary, should check GitHub for latest
4. **No XDG config** - should create `${XDG_CONFIG_HOME}/star/config.yaml`

## Requirements

### LKG Release Process

Release candidates cycle until validation passes, then promote to LKG.

**Workflow**:

```bash
make rc          # v0.1.0-rc.1 - bump RC, run tests (fails)
# fix issues
make rc          # v0.1.0-rc.2 - bump RC, run tests (fails)
# fix issues
make rc          # v0.1.0-rc.3 - bump RC, run tests (passes!)
make release     # v0.1.0 - promote to LKG, clean up RCs
```

**Commands**:

| Command | Description |
| --- | --- |
| `make release-candidate` | Bump RC number, run tests, report pass/fail |
| `make rc` | Alias for `release-candidate` |
| `make release` | Promote passing RC to LKG, delete RC tags |
| `make clean-rc` | Delete all RC tags without releasing |

**Version format**:

```text
v0.1.0-rc.20260206T143022-abc1234    # RC: pre-release with timestamp + commit
v0.1.0+20260206T151033.ghi9012       # LKG: release with build metadata
v0.1.0                                # Clean tag (points to same commit as above)
```

**Sorting** (semver compliant):

```text
v0.1.0-rc.* < v0.1.0 = v0.1.0+metadata
```

Pre-release (`-rc.*`) sorts before release. Build metadata (`+`) is ignored in sorting.

**Version progression**:

```text
v0.1.0-rc.20260206T143022-abc1234  ← first attempt (fails)
v0.1.0-rc.20260206T145512-def5678  ← second attempt (fails)
v0.1.0-rc.20260206T151033-ghi9012  ← passes validation
v0.1.0+20260206T151033.ghi9012     ← promoted to LKG (RCs deleted)
v0.1.0                              ← clean tag (same commit)
```

**Release artifacts** (LKG only):

```text
star_v0.1.0_darwin_amd64.tar.gz
star_v0.1.0_darwin_arm64.tar.gz
star_v0.1.0_linux_amd64.tar.gz
star_v0.1.0_linux_arm64.tar.gz
star_v0.1.0_windows_amd64.zip
checksums.txt
```

### Validation Tests

Release is blocked unless star passes behavior tests:

```bash
make validate
```

**Tests**:

| Test | Description |
| --- | --- |
| `star --version` | Outputs version string |
| `star lint go` | Runs golangci-lint successfully |
| `star lint shell` | Runs shellcheck/shfmt successfully |
| `star lint markdown` | Runs markdownlint successfully |
| `star setup tools` | Reports tool status |
| `star setup config` | Generates configs from star.yaml |
| `star self install --prefix /tmp/test` | Installs completions, man pages, config |

These are smoke tests ensuring core functionality works before release.

### Bootstrap Install Script

Initial install for machines without star.

**Note**: noblefactor-ops is a **private repository**. Bootstrap scripts require `GH_TOKEN` with Contents read permission (same as devlore-cli).

**macOS/Linux (bash)**:

```bash
curl -sSL https://raw.githubusercontent.com/NobleFactor/noblefactor-ops/develop/scripts/install-star.sh | GH_TOKEN=$(gh auth token) bash
```

**Windows (PowerShell)**:

```powershell
$env:GH_TOKEN = (gh auth token); irm https://raw.githubusercontent.com/NobleFactor/noblefactor-ops/develop/scripts/install-star.ps1 | iex
```

**What the scripts do**:

1. Verify `GH_TOKEN` is set (required for private repo)
2. Detect OS and architecture
3. Download latest LKG release from GitHub (via authenticated API)
4. Verify checksum
5. Extract to platform-appropriate location:
   - Unix: `~/.local/bin/star`
   - Windows: `~\AppData\Local\star\bin\star.exe`
6. Run `star self install` to generate man pages, completions, config
7. Print PATH instructions

### Self Install (Local)

Generate supporting files locally - no network required:

```bash
star self install                   # Default: ~/.local
star self install --prefix /usr/local
```

**What it does**:

1. Generate and install to XDG locations:
   - `${XDG_DATA_HOME}/man/man1/star*.1` (man pages)
   - `${XDG_DATA_HOME}/bash-completion/completions/star` (bash)
   - `${XDG_DATA_HOME}/fish/vendor_completions.d/star.fish` (fish)
   - `${XDG_DATA_HOME}/zsh/site-functions/_star` (zsh)
   - `${XDG_DATA_HOME}/powershell/Completions/star.ps1` (PowerShell)
   - `${XDG_CONFIG_HOME}/star/config.yaml` (config placeholder)
2. Report what was installed

**Key behaviors**:

- Works offline - no network required
- Idempotent - safe to run anytime
- XDG compliant

### Self Upgrade (Network)

Check for and install newer LKG release:

```bash
star self upgrade                    # Requires GH_TOKEN for private repo
```

**What it does**:

1. Check current version vs latest LKG on GitHub (requires `GH_TOKEN`)
2. If newer version available:
   - Download release tarball (uses cache if available)
   - Verify checksum
   - Replace binary at `<prefix>/bin/star`
3. Run `self install` to regenerate completions/man pages
4. Report what was updated

**Key behaviors**:

- Requires network and `GH_TOKEN` (private repo)
- Fail-fast on network errors
- Uses release cache to reduce downloads
- No-op if already at latest LKG

### Release Caching

Downloaded releases are cached to reduce redundant downloads:

**Cache location**: `${XDG_CACHE_HOME}/star/releases/`

**Structure**:

```text
${XDG_CACHE_HOME}/star/releases/
├── star_v0.1.0_darwin_arm64.tar.gz
├── star_v0.1.0_darwin_arm64.tar.gz.sha256
└── latest.txt  # Last known LKG version
```

**Behavior**: If cached tarball matches latest version and checksum is valid, skip download.

### Error Handling

**self install**: Always succeeds (local operations only).

**self upgrade**: Fail-fast on network errors:

```text
error: failed to fetch latest release: connection refused
error: GH_TOKEN required for private repository access
error: checksum verification failed for star_v0.1.0_darwin_arm64.tar.gz
```

This keeps behavior predictable - if something goes wrong, the user knows immediately.

### Embedded Scripts

All `.star` scripts are embedded in the binary via `//go:embed`:

```go
//go:embed ops/*.star
var embeddedOps embed.FS
```

**Benefits**:

- Single binary distribution - no external files to manage
- Version consistency - scripts match binary version
- Simpler upgrades - replace one file

### Script Search Path

At runtime, star searches for scripts in this order:

| Priority | Location | Purpose |
| --- | --- | --- |
| 1 | `./ops/*.star` | Project-specific scripts (repo) |
| 2 | `${XDG_DATA_HOME}/star/ops/*.star` | Extracted scripts (debugging) |
| 3 | Embedded | Fallback (always works) |

First match wins. This allows:

- Repos to override/extend global commands
- Developers to extract and modify scripts for debugging
- Guaranteed fallback to embedded code

### Extract Scripts for Debugging

```bash
star self install --extract-scripts
```

Extracts embedded scripts to `${XDG_DATA_HOME}/star/ops/`:

```text
${XDG_DATA_HOME}/star/ops/
├── lint.star
├── lint-copyright.star
├── lint-frontmatter.star
├── lint-starlark.star
├── setup.star
└── ...
```

To revert to embedded: `rm -rf ${XDG_DATA_HOME}/star/ops/`

### Version Bumping

```bash
make bump-patch   # 0.1.0 → 0.1.1
make bump-minor   # 0.1.0 → 0.2.0
make bump-major   # 0.1.0 → 1.0.0
```

**Validation** - `scripts/bump-version.sh` ensures no gaps:

```bash
#!/bin/bash
# scripts/bump-version.sh - Bump version with gap validation

set -euo pipefail

CURRENT=$(cat VERSION)
LAST_TAG=$(git describe --tags --abbrev=0 2>/dev/null | sed 's/^v//' | sed 's/-rc\.[0-9]*//' || echo "0.0.0")

IFS='.' read -r MAJOR MINOR PATCH <<< "$CURRENT"
IFS='.' read -r LAST_MAJOR LAST_MINOR LAST_PATCH <<< "$LAST_TAG"

case "$1" in
  patch)
    NEW="$MAJOR.$MINOR.$((PATCH + 1))"
    # Must follow released version
    if [[ "$MAJOR.$MINOR" != "$LAST_MAJOR.$LAST_MINOR" ]]; then
      echo "ERROR: Cannot bump patch - VERSION $CURRENT doesn't match last release $LAST_TAG"
      exit 1
    fi
    ;;
  minor)
    NEW="$MAJOR.$((MINOR + 1)).0"
    # Minor must be exactly +1 from last released minor
    if [[ "$MAJOR" != "$LAST_MAJOR" ]] || [[ "$((MINOR))" -lt "$LAST_MINOR" ]]; then
      echo "ERROR: Cannot bump minor - would create gap from $LAST_TAG"
      exit 1
    fi
    ;;
  major)
    NEW="$((MAJOR + 1)).0.0"
    # Major must be exactly +1 from last released major
    if [[ "$((MAJOR))" -lt "$LAST_MAJOR" ]]; then
      echo "ERROR: Cannot bump major - would create gap from $LAST_TAG"
      exit 1
    fi
    ;;
  *)
    echo "Usage: $0 {patch|minor|major}"
    exit 1
    ;;
esac

echo "$NEW" > VERSION
echo "Bumped version: $CURRENT → $NEW"
```

### VERSION File

Version is tracked in a `VERSION` file:

```text
0.1.0
```

The Makefile reads this file and validates version bumps.

### Makefile Targets

```makefile
# Makefile

.PHONY: build test validate release-candidate rc release clean-rc bump-patch bump-minor bump-major

# Version from file
BASE_VERSION := $(shell cat VERSION 2>/dev/null || echo "0.0.0")
TIMESTAMP := $(shell date -u +%Y%m%dT%H%M%S)
SHORT_COMMIT := $(shell git rev-parse --short HEAD)
RC_VERSION := v$(BASE_VERSION)-rc.$(TIMESTAMP)-$(SHORT_COMMIT)
RELEASE_VERSION := v$(BASE_VERSION)+$(TIMESTAMP).$(SHORT_COMMIT)
CLEAN_VERSION := v$(BASE_VERSION)

# Version bump targets
bump-patch:
 @./scripts/bump-version.sh patch

bump-minor:
 @./scripts/bump-version.sh minor

bump-major:
 @./scripts/bump-version.sh major

build:
 go build -o star ./cmd/star

test:
 go test ./...

validate: build
 @echo "Running behavior validation..."
 ./star --version
 ./star lint go
 ./star lint shell
 ./star lint markdown
 ./star setup tools
 ./star setup config
 @echo "Validation PASSED"

# Create release candidate - run tests, tag on success
release-candidate:
 @echo "Testing $(RC_VERSION)..."
 @$(MAKE) test validate || (echo "FAILED - fix and run 'make rc' again" && exit 1)
 git tag $(RC_VERSION)
 @echo "$(RC_VERSION) PASSED - run 'make release' to promote to LKG"

# Alias
rc: release-candidate

# Promote to LKG release
release:
 @echo "Releasing $(RELEASE_VERSION)..."
 @$(MAKE) test validate || (echo "FAILED - validation must pass" && exit 1)
 git tag $(RELEASE_VERSION)
 git tag $(CLEAN_VERSION)
 goreleaser release --clean
 @$(MAKE) clean-rc
 @echo "Released $(CLEAN_VERSION) ($(RELEASE_VERSION))"

# Clean up RC tags
clean-rc:
 @echo "Removing RC tags for v$(BASE_VERSION)..."
 @git tag -l "v$(BASE_VERSION)-rc.*" | xargs -r git tag -d
 @git push origin --delete $(shell git tag -l "v$(BASE_VERSION)-rc.*") 2>/dev/null || true
```

## Implementation Phases

### Phase 1: Version Flag and Makefile

1. Create `VERSION` file with initial version (0.1.0)

2. Create `scripts/bump-version.sh`:
   - `bump-patch`, `bump-minor`, `bump-major`
   - Validates no version gaps

3. Add version variables to `cmd/star/main.go`:
   - `var version = "dev"`
   - `var commit = "unknown"`
   - Add `--version` flag

4. Create `Makefile`:
   - `make build` - Build star binary
   - `make test` - Run unit tests
   - `make validate` - Run behavior smoke tests
   - `make bump-{patch,minor,major}` - Bump VERSION file
   - `make release-candidate` (alias: `make rc`) - Create RC, run tests
   - `make release` - Promote passing RC to LKG
   - `make clean-rc` - Remove RC tags

5. Test: `make validate` passes on current code

### Phase 2: Release Workflow

1. Create `.goreleaser.yaml`:
   - Build for darwin/linux/windows × amd64/arm64
   - Single binary (scripts embedded, no external files)
   - Generate checksums
   - ldflags for version embedding
   - **Model**: `devlore-cli/.goreleaser.yaml` (simpler: single binary, no nfpms/brews)

2. Create `.github/workflows/release.yaml`:
   - Trigger on `v*` tags
   - Run `make test` and `make validate`
   - Run goreleaser
   - Create GitHub release with artifacts

3. Test: `make release` creates release with binaries

### Phase 3: Embed Scripts with Search Path

1. Create `ops/embed.go`:

   ```go
   //go:embed *.star
   var Scripts embed.FS
   ```

2. Update `internal/starlark/loader.go`:
   - Implement search path: `./ops/` → `${XDG_DATA_HOME}/star/ops/` → embedded
   - First match wins

3. Add `--extract-scripts` flag to `self install`:
   - Extract embedded scripts to `${XDG_DATA_HOME}/star/ops/`
   - For debugging/development

4. Test:
   - `star lint go` works with embedded scripts
   - Extracted scripts override embedded
   - Repo scripts override both

### Phase 4: Self Command with Install and Update Subcommands

1. Create `self` parent command with subcommands:
   - `star self install` - generates local files (no network)
   - `star self upgrade` - checks and downloads LKG (network)

2. Update `internal/cli/self_install.go`:
   - Default to `~/.local` (XDG compliant)
   - Add `--prefix` flag to override
   - Generate man pages to `${XDG_DATA_HOME}/man/man1/`
   - Generate completions for all shells:
     - `${XDG_DATA_HOME}/bash-completion/completions/star`
     - `${XDG_DATA_HOME}/fish/vendor_completions.d/star.fish`
     - `${XDG_DATA_HOME}/zsh/site-functions/_star`
     - `${XDG_DATA_HOME}/powershell/Completions/star.ps1`
   - Create `${XDG_CONFIG_HOME}/star/config.yaml`
   - No network required

3. Add `internal/cli/self_upgrade.go`:
   - Requires `GH_TOKEN` environment variable
   - Check current version vs latest LKG on GitHub
   - If newer: download, verify checksum, replace binary
   - Call `self install` to regenerate completions

4. Add `internal/cli/release.go`:
   - GitHub release API client (authenticated via `GH_TOKEN`)
   - `GetLatestRelease()` - fetch latest LKG version
   - `DownloadRelease(version, os, arch)` - download tarball
   - Release caching in `${XDG_CACHE_HOME}/star/releases/`

5. Test:
   - `star self install` generates completions without network
   - `star self upgrade` downloads newer LKG if available

**Reference implementation**: See `devlore-cli/internal/cli/selfinstall.go` for:

- `detectShells()` - auto-detect available shells (bash, fish, powershell, zsh)
- `shellCompletionPath()` - XDG-compliant paths for each shell
- `installCompletionsForShells()` - generate completions using Cobra's Gen* functions

### Phase 5: Bootstrap Scripts

1. Create `scripts/install-star.sh` (bash for macOS/Linux):
   - Detect OS (darwin/linux) and arch (amd64/arm64)
   - Download latest release from GitHub
   - Extract to `~/.local/bin`
   - Run `star self install`
   - Print PATH instructions

2. Create `scripts/install-star.ps1` (PowerShell for Windows):
   - Detect arch (amd64)
   - Download latest release from GitHub
   - Extract to `~/AppData/Local/star/bin`
   - Run `star self install`
   - Print PATH instructions (update `$env:Path`)

3. Test: Fresh machine can run bootstrap script to install star

**Reference implementation**: See `devlore-cli/install.sh` for:

- GitHub release API usage (authentication, asset download)
- Platform detection (OS and architecture)
- Checksum verification
- Running `self install` after binary extraction

## Migration Path

### For noblefactor-ops maintainers

1. After Phase 1: `make validate` ensures star works before committing
2. After Phase 2: Release workflow:

   ```bash
   make rc        # Create RC, run tests (repeat until passing)
   make release   # Promote to LKG, clean up RCs
   ```

3. Release creates GitHub release with downloadable binaries

### For developers in other repos

**Initial install** (no star):

```bash
curl -fsSL .../install-star.sh | bash
```

**Updates** (star already installed):

```bash
star self upgrade
```

Then:

1. Run `star setup config` to generate quality gate configs
2. Pre-commit hooks are ready

**Installation layout** (XDG compliant):

```text
~/.local/bin/star                                    # Binary (scripts embedded)
${XDG_DATA_HOME}/star/ops/*.star                     # Extracted scripts (optional, for debugging)
${XDG_DATA_HOME}/man/man1/star*.1                    # Man pages (generated)
${XDG_DATA_HOME}/bash-completion/completions/star    # Bash completion (generated)
${XDG_DATA_HOME}/fish/vendor_completions.d/star.fish # Fish completion (generated)
${XDG_DATA_HOME}/zsh/site-functions/_star            # Zsh completion (generated)
${XDG_DATA_HOME}/powershell/Completions/star.ps1     # PowerShell completion (generated)
${XDG_CONFIG_HOME}/star/config.yaml                  # User config
```

**Script search path**: `./ops/` → `${XDG_DATA_HOME}/star/ops/` → embedded

### For CI/CD

1. CI runs bootstrap script or `star self upgrade` to ensure latest LKG
2. No need for `go run ./cmd/star` - use installed binary
