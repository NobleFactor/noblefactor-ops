# Plan: Star as Unified Quality Gate

<!--

-->

## Summary

Make `star` the single source of truth for pre-commit hooks and quality gates across all NobleFactor repositories. Running `star setup config` in any repo generates `.pre-commit-config.yaml` (and other tool configs) from `star.yaml`, ensuring consistent quality gates everywhere.

## Goals

1. **Single tool**: `star` manages all quality checks
2. **Unified config**: `star.yaml` is the single source of truth
3. **Generated configs**: `.pre-commit-config.yaml`, `.golangci.yaml`, `.markdownlint-cli2.yaml` are all generated from `star.yaml`
4. **Cross-repo consistency**: Every repo runs `star setup config` and gets identical quality gates
5. **Extensible**: New checks added via Starlark scripts

### Gap: Pre-commit Calls Tools Directly

Current `.pre-commit-config.yaml` is **manually maintained** and calls tools directly:

```yaml
# Current: calls tools directly (BAD)

  entry: golangci-lint run --config .golangci.yaml
- id: shfmt
  entry: shfmt -d -i 4 -ci
- id: shellcheck
  entry: shellcheck -x --severity=warning
```

This duplicates configuration and bypasses `star` as the quality gate.

## Requirements

### Generate `.pre-commit-config.yaml` (REQUIRED)

`star setup config` must generate `.pre-commit-config.yaml` that calls `star lint` directly.

**This is the primary deliverable** - it solves the cross-repo consistency problem by ensuring every repo gets the same pre-commit hooks from a single source of truth.

**Generated `.pre-commit-config.yaml`**:

```yaml
# GENERATED BY star lint sync - DO NOT EDIT
# Source: star.yaml
# Regenerate: star setup config

repos:
  - repo: local
    hooks:
      - id: star-lint-all
        name: Star quality gate
        entry: star lint all --
        language: system
        pass_filenames: true
        types: [file]
```

**Staged files**: Pre-commit passes the list of staged files to `star lint all`. Each linter filters for its file types (go, shell, markdown, etc.).

**Why this matters**:

- `star.yaml` is the single source of truth
- Pre-commit becomes a thin wrapper around `star lint`
- No configuration duplication between `.pre-commit-config.yaml` and `star.yaml`
- Adding a new linter to `star.yaml` automatically includes it in pre-commit

**Configuration** (`star.yaml`):

```yaml
precommit:
  hooks:
    - id: star-lint-all
      name: Star quality gate
      entry: star lint all
      stages: [pre-commit]
    - id: star-test
      name: Run tests
      entry: star test go
      stages: [pre-push]  # Optional: pre-push only
```

**Note**: `.pre-commit-config.yaml` generation is **required** for cross-repo consistency. Every repo with a `star.yaml` gets a generated `.pre-commit-config.yaml`.

**Commands**:

```bash
star setup config             # Generate .pre-commit-config.yaml (and other configs)
star setup config --clean     # Remove generated configs
```

### Copyright Header Checks

All source files must have SPDX license headers. No years in copyright - the LICENSE file timestamp is authoritative.

**Format** (go example):

```go
// SPDX-License-Identifier: MIT
// Copyright Noble Factor. All rights reserved.
```

**Configuration** (`star.yaml`):

```yaml
lint:
  copyright:
    enabled: true
    license: MIT           # SPDX identifier, or "auto" to detect from LICENSE file
    holder: Noble Factor
    patterns:
      go: |
        // SPDX-License-Identifier: {license}
        // Copyright {holder}. All rights reserved.
      star: |
        # SPDX-License-Identifier: {license}
        # Copyright {holder}. All rights reserved.
      shell: |
        # SPDX-License-Identifier: {license}
        # Copyright {holder}. All rights reserved.
    exclude:
      - "**/testdata/**"
      - "**/vendor/**"
      - "**/*_generated.go"
```

**License auto-detection**: When `license: auto`, parses the LICENSE file to detect the SPDX identifier (MIT, Apache-2.0, SSPL-1.0, etc.).

**File types**: Only source code files (go, star, shell). YAML and markdown files are covered by the root LICENSE file and don't need inline headers.

**Commands**:

```bash
star lint copyright           # Check headers (report missing/mismatched)
star lint copyright --fix     # Add missing headers, update old format (remove years)
```

**Fix behavior**:

- Files without headers: Add the configured header
- Files with old format (containing years): Replace with new format
- Files with wrong license/holder: Replace with correct values

### Frontmatter Validation

Markdown guides must have valid YAML frontmatter:

```yaml
---
title: Guide Title
description: One-line description
category: guides/lore
tags: [deployment, packages]
---
```

**Configuration** (`star.yaml`):

```yaml
frontmatter:
  required_fields:
    - title
    - description
  optional_fields:
    - category
    - tags
    - author
    - date
  paths:
    - "docs/guides/**/*.md"
    - "docs/cli/**/*.md"
  exclude:
    - "**/README.md"
    - "docs/index.md"
```

**Commands**:

```bash
star lint frontmatter         # Validate frontmatter
star lint frontmatter --fix   # Generate missing frontmatter (interactive)
```

### YAML/JSON Schema Validation

Validate config files against JSON schemas:

**Configuration** (`star.yaml`):

```yaml
lint:
  yaml:
    enabled: true
    schemas:
      - pattern: "star.yaml"
        schema: "https://noblefactor.com/schemas/star-v1.json"
      - pattern: "**/packages-manifest.yaml"
        schema: "https://noblefactor.com/schemas/packages-manifest-v1.json"
      - pattern: ".github/workflows/*.yaml"
        schema: "https://json.schemastore.org/github-workflow.json"
    exclude:
      - "**/testdata/**"
```

**Commands**:

```bash
star lint yaml                # Validate YAML/JSON against schemas
```

**Note**: Uses JSON Schema validation. Schemas can be URLs (fetched and cached) or local file paths.

### Starlark Linting

Lint `.star` files for formatting and complexity.

**Tools**:

- **Buildifier** - Standard Starlark formatter/linter (~100 checks)
- **Custom complexity** - Function length, nesting depth, conditionals

**Configuration** (`star.yaml`):

```yaml
lint:
  starlark:
    enabled: true
    buildifier:
      warnings: all  # or specific: [+-warn1, +-warn2]
    complexity:
      max_function_lines: 50
      max_nesting_depth: 4
      max_conditionals: 10  # Poor man's cyclomatic complexity
```

**Commands**:

```bash
star lint starlark            # Check formatting and complexity
star lint starlark --fix      # Auto-format with buildifier
```

**Why custom complexity**: Starlark is a Python dialect but lacks `import`, `class`, `try/except`. Python tools (ruff, pylint) produce many false positives. Buildifier handles formatting; we add simple complexity metrics.

### Native Git Hooks

Replace pre-commit framework with star-managed hooks:

**Hook installation**:

```bash
star setup hooks              # Install star as git hook
```

**Generated `.git/hooks/pre-commit`**:

```bash
#!/bin/sh
exec star hook pre-commit "$@"
```

**Hook execution**:

```bash
star hook pre-commit          # Run pre-commit checks
star hook pre-push            # Run pre-push checks (optional)
```

**Configuration** (`star.yaml`):

```yaml
hooks:
  pre-commit:
    - lint go
    - lint shell
    - lint markdown
    - lint starlark
    - lint copyright
    - lint frontmatter
  pre-push:
    - test go
```

### Unified Lint Command

```bash
star lint all                 # Run all configured linters
star lint all --fix           # Run all with auto-fix where supported
```

**Failure behavior**: Run all linters regardless of failures. Collect and display all errors. Exit non-zero if any linter failed. This maximizes feedback per run.

**Missing tools**: If a required tool (golangci-lint, shellcheck, buildifier, etc.) is not installed, `star lint all` fails immediately with a clear error message directing the user to run `star setup tools`.

**Config validation**: `star.yaml` is validated on every command invocation. Invalid config (unknown keys, wrong types, missing required fields) causes immediate failure with a clear error message pointing to the problem.

**CI workflow example**:

```yaml
jobs:
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      # Cache star binary and releases
      - uses: actions/cache@v4
        with:
          path: |
            ~/.local/bin/star
            ~/.cache/star/releases
          key: star-${{ runner.os }}-${{ runner.arch }}

      # Install or update star
      - name: Install star
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: |
          if command -v star &>/dev/null; then
            star self upgrade || true
          else
            curl -sSL https://raw.githubusercontent.com/NobleFactor/noblefactor-ops/develop/scripts/install-star.sh | bash
          fi

      # Run quality gate
      - run: star lint all
```

### Prerequisite: Config Starlark Bindings

Before Phase 4 (Copyright), the config module must properly convert Go structs to Starlark structs with attribute access.

**Current problem**: `configToStarlark()` uses YAML round-trip to convert to `map[string]interface{}`, then to Starlark dict. This loses struct semantics and requires dict access (`cfg["lint"]["copyright"]`) instead of attribute access (`cfg.lint.copyright`).

**Required pattern** (matches devlore-cli):
- Use `starlarkstruct.FromStringDict()` for namespaced objects with attribute access
- Use `starlark.NewDict()` only for actual configuration dictionaries (e.g., `settings`)
- Each nested struct gets its own `ToStarlark()` method

**Implementation**:

1. Add `ToStarlark()` method to each config struct:

   ```go
   // internal/config/starlark.go

   func (c *Config) ToStarlark() starlark.Value {
       return starlarkstruct.FromStringDict(starlarkstruct.Default, starlark.StringDict{
           "lint":      c.Lint.ToStarlark(),
           "precommit": c.Precommit.ToStarlark(),
       })
   }

   func (l *LintConfig) ToStarlark() starlark.Value {
       return starlarkstruct.FromStringDict(starlarkstruct.Default, starlark.StringDict{
           "go":        l.Go.ToStarlark(),
           "shell":     l.Shell.ToStarlark(),
           "markdown":  l.Markdown.ToStarlark(),
           "copyright": l.Copyright.ToStarlark(),
       })
   }

   func (c *CopyrightLintConfig) ToStarlark() starlark.Value {
       // Convert patterns map to dict
       patterns := starlark.NewDict(len(c.Patterns))
       for k, v := range c.Patterns {
           patterns.SetKey(starlark.String(k), starlark.String(v))
       }

       // Convert exclude list
       var exclude []starlark.Value
       for _, e := range c.Exclude {
           exclude = append(exclude, starlark.String(e))
       }

       return starlarkstruct.FromStringDict(starlarkstruct.Default, starlark.StringDict{
           "enabled":  starlark.Bool(c.Enabled),
           "license":  starlark.String(c.License),
           "holder":   starlark.String(c.Holder),
           "patterns": patterns,
           "exclude":  starlark.NewList(exclude),
       })
   }
   ```

2. Update `internal/starlark/builtin_config.go`:
   - Replace `configToStarlark()` with call to `cfg.ToStarlark()`
   - Remove `mapToStarlark()` and `valueToStarlark()` helpers

3. Update Starlark scripts to use attribute access:
   - `cfg.lint.copyright.enabled` instead of `cfg["lint"]["copyright"]["enabled"]`

**Files to modify**:

| File | Action |
| --- | --- |
| `internal/config/starlark.go` | Create - ToStarlark() methods for all config structs |

## Configuration Schema

Full `star.yaml` schema:

```yaml
# star.yaml - Unified quality gate configuration

lint:
  go:
    enabled: true
    config:  # Inline golangci-lint config (generates .golangci.yaml)
      linters:
        enable: [gofmt, govet, errcheck, staticcheck]
      linters-settings:
        gocyclo:
          min-complexity: 15
  shell:
    enabled: true
    shellcheck:
      severity: warning
    shfmt:
      indent: 4
  markdown:
    enabled: true
    config:  # Inline markdownlint config (generates .markdownlint-cli2.yaml)
      MD013: false
      MD033: false
  starlark:
    enabled: true
    buildifier:
      warnings: all
    complexity:
      max_function_lines: 50
      max_nesting_depth: 4
      max_conditionals: 10
  copyright:
    enabled: true
    license: MIT        # SPDX identifier, or "auto" to detect from LICENSE
    holder: Noble Factor
    patterns:
      go: |
        // SPDX-License-Identifier: {license}
        // Copyright {holder}. All rights reserved.
      star: |
        # SPDX-License-Identifier: {license}
        # Copyright {holder}. All rights reserved.
      shell: |
        # SPDX-License-Identifier: {license}
        # Copyright {holder}. All rights reserved.
    exclude:
      - "**/testdata/**"
      - "**/vendor/**"
  frontmatter:
    enabled: true
    required_fields: [title, description]
```
